# A4 (verification audit of 2026-11-17), made exact: a hook's loop pushes each listener on its passed-in choice context first
# thing, and PlayerChoiceContext.PushModel creates the context's model stack on its first call, so a filtered walk that kept
# nothing where the game's walk yields something would leave the stack null where the game leaves it empty. HookSkip's filters
# keep every badge, a state without one walks vanilla (the badge guard), and the walks over the game's own walk (KeptOnly, when
# another mod patches a walk) keep its first listener. Mod on, singleplayer, starter deck (small: more hooks with no reacting
# listener, so the control below finds emptied walks); compares nothing with another session (bdperf badges clear changes the
# run's listeners). Both supported game versions.
# (1) The game's runs: no filtered walk emptied, the guard never needed, KeptOnly unused.
# (2) bdperf badges clear (a state the game never makes): every filtered walk goes to the game's walk (HookSkip.NoBadge grows,
#     HookSkip's filtered walks stay the same), none emptied.
# (3) Positive control of HookSkip.Emptied: the guard off on that state, the filtered walks run anyway and some end empty.
# (4) Another mod on both walks (fakeconflict): the filtered walks go through the game's walk (KeptOnly), which keeps its first
#     listener (FastListeners.FirstKept grows, counted for HookSkip's walks only: a run walk's first deck card), and none ends
#     empty even with no badge and the guard still off. Weak on its own: KeptOnly drops only pile entries, so a walk with a power,
#     relic or monster never ends empty there anyway; that the stack is created at the game's moment on this path is argued
#     (DESIGN A4), not measured.
