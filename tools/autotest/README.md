# Unattended in-game tests

Drive the real game with the **Debug** build's `AutoTest` runner (`src/BigDeckOptimization/Bench/AutoTest.cs`): it only
starts when the game is launched with `--bdtest <scenario>`, so normal launches are unaffected. Results (game logs,
traces) go to `results/` (gitignored).

| Script | What |
|---|---|
| `run.ps1 -Name <scenario> [-TraceSec 60] [-KeepConfig] [-Visible] [-Sound] [-Screen 1]` | Singleplayer on a game copy (`-GameDir` or `STS2_GAME_DIR`), or through Steam only with a Debug build in the Steam install's mods folder (`try.ps1 -SteamInstall`): the Workshop's Release build has no test runner, so without one the Steam path is refused. A game whose test runner logs no line within 90 s (no Debug build in the copy, the mod not loaded) is closed (`AUTOTEST NOT LOADED`); through Steam the game is waited for 3 minutes, then looked for once more and closed if it starts late (the marker stays for the next run). Exit code 1 when the session has a problem. Save profile 3, in memory only: your profiles and last-profile setting are untouched). The game window is moved off-screen (windowed 1920x1080, still rendering: same screenshots and fps) and gives the focus back to the window you were using; on a copy it starts hidden and takes no keyboard (through Steam it shows on screen `-Screen` for a moment, as Steam launches it); `-Visible` keeps it on screen. The game is muted (every master volume it sets is 0, your volume settings are untouched); `-Sound` keeps the sound. Only the window and the live volume change, not your settings. On a game copy (`-GameDir`) the session runs without Steam in its own user data, as `par.ps1`; `-KeepSlot` keeps that user data from the previous session (`settings.ps1`, `baselib-optional.ps1`, `limitless-switches.ps1`, for a check over a restart). | `python -I judge.py [--no-end] <log> [<log> ...]` | Whether a session's log shows a problem, the one rule every runner uses (par, parcoop, coop4, parsweep's report, compare, mutations, release-incopy, run.ps1 and coop.ps1 print it); its last line is `JUDGED <n> problem(s)`, and a runner that doesn't see it counts the logs as failed (the judge crashed). A problem: the session didn't reach its end; the game's auto player (`autoslay`) failing before its run's end (it logs `Quitting` either way; with Limitless the last event never hands back the game over screen, so that failure after the final act's boss is the end); a co-op `State divergence`; an error the game logs whose stack goes through this mod's code (not `Bench`): a `[ERROR]` line, or Godot's own `ERROR: System.X` head (an exception in an engine callback; the engine's other `ERROR:` lines have no frame of this mod); a failed line (a failed console command included), `ABORT`, the script's `TIMEOUT`, `SWEEP FAILED`/`ABORT`; any error this mod logs (its patches log errors only when they turn themselves off, find a difference with the game's result, or can't apply); any warning it logs (an exception caught in its own code, part of its work not done: a left run's caches not released, a switch not set...), but the few intended ones listed in `MOD_WARN_OK` (the settings menu missing, the menu's co-op refusal of the master switch, a fault's retried removal, a mirrored hook passing the game's own exception on, the test tooling's probes); `MISMATCH`, `mismatches N`, `differs from`, `changed unseen`; the mod off from the start (saved settings); a `LEAKCHECK` reaching a left run, `current` finding nothing, or `INCONCLUSIVE`. A positive control declares what it provokes with `expect <regex>`; a regex that matches nothing is a problem too, and so is one Python can't compile (.NET checks it when the script runs). |

Prerequisites: a Debug build deployed into the game copy (`dotnet build src\BigDeckOptimization\BigDeckOptimization.csproj -c Debug -p:ModDeployDir=<copy>\mods\BigDeckOptimization`), `dotnet-trace` on PATH for traces, a run history file
copied to `%APPDATA%\SlayTheSpire2\bigdeck\ref.run` (scenarios import its decks and relics). Before the first co-op
test, launch the game once with `--force-steam off` and accept the mods warning (each non-Steam instance has its own
data folder, `%APPDATA%\SlayTheSpire2\default\<id>`).

## Scenario lines

One command per line, `#` comments, `{hash:NAME}` replaced by the hash of `bigdeck/NAME.run`.

- `newrun <CHARACTER> [seed]`, `mplobby <CHARACTER> [players] [seed]` (co-op lobby: pick and ready up; the host sets the run seed, default `BDTEST` as `newrun`, so an on/off pair plays the same run: without it the game drew one from the clock up to v0.111 and a random one since v0.113)
- `wait <s>`, `waitfor menu|run|combat|idle|nocombat|turn|deckcount|restsite|event [timeout s]` (`turn`: ready to play or the combat over, without waiting for the other peer; `deckcount`: the deck count shown; `restsite`/`event`: this player's options there), `waitfor round <n> [timeout s]` (that round begun and this player able to act, or the combat over), `waitfor room <type> [timeout s]`, `timeout <s>` (whole script)
- `uncap` (no fps cap, no vsync: frame times above the screen's refresh rate), `gcpacing off|on` (this mod's memory cleanups at quiet moments, for the session), `avoid <ID,ID...>` (cards `play` never picks), `pilemove <from> <to> [keep]` (moves a pile's cards to another silently, leaving the first `keep` ones: a huge discard pile for the next reshuffle), `decksort` (the deck view sorted by cost then title, as its buttons do), `deckpages <prefix> <pages>` (deck view screenshots two card rows per page), `watch <s>` (4 lines a second, in the background: card previews on screen and the deck size), `nodes [label]` (scene nodes, card previews, cards flying to a pile), `menuvalues [label]` (what BaseLib's menu shows for each switch, `MENU` line), `patchlist` (every patched method, its patch kinds and owners: `PATCHED` lines), `faultprobe` (this mod's fault handling exercised on test patches: `FAULTPROBE`, the line fails on a `FAILED`)
- `cmd <console command>` (networked commands go through the action queue in co-op: there the line only enqueues them, and one that fails when the queue runs it, on any peer, logs `FAILED: networked command ...` and fails the next line or wait; so does a command whose returned task faults when the queue awaits it)
- `play <n>`, `playcard <ID> [enemy index] [free] [optional]` (after `cmd card <ID> hand`; `free`: energy and star costs 0 first, not X costs; every card play, auto-plays included, is logged as `CARDPLAY`), `endturn`
- `restsite <X>RestSiteOption [optional]`, `eventoption <text key part> [timeout s] [optional]` (picks that rest site or event option like a click, timed)
- What a step needs and doesn't find (a card not in hand or not playable, a rest site or event option, a shop's card removal, `autoroom`'s named rest site option) fails the line; `optional` when the scenario may legitimately lack it (e.g. a co-op client without the relic giving the option), then it logs `skipped (optional)`.
- `enemyhp <hp>` (next combats), `state [label] [optional]` (creatures, powers, piles; outside a combat the line fails unless `optional`: use `runstate` there), `speed normal|fast|instant` (default fast)
- `deckview [s] [shot]`, `deckscroll <steps>`, `screenshot <name>`, `modsscreen <shot>`, `baselibmenu <shot>` (this mod's page in BaseLib's settings)
- `pilescroll draw|discard|exhaust <frames> [px]` (opens a combat pile view and moves its scroll target every frame like a held mouse wheel: open time, ms per frame, median/95th/worst; 3000 px steps redraw the whole grid like dragging the scrollbar)
- `language <code>` (game language for the session only, e.g. `fra`, `zhs`, `zht`; logs this mod's menu texts as `LANG` lines), `menuback` (closes the current main-menu submenu), `menutext <SLUG>` (logs an option's tooltip text, e.g. `HOOK_FILTER`, as `MENUTEXT`)
- `deckfilter [ID,ID...] [stacked]` (on the map: removes cards by id and, with `stacked`, those holding several stacked Limitless enchantments)
- `fakeconflict <Type:Method> [boolprefix]` (a no-op postfix under another Harmony id, as another mod would patch that method, or a prefix returning true: the optimization using it backs off and names it, unless its check lets that shape stand; `conflict-check`)
- `foreignpatch <shape> <Namespace.Type:Method> [gate] [priority N]` (synthetic patches of another mod, Harmony ids `bdtest.foreign.<shape>`, `Bench/ForeignPatches.cs`: `noop-postfix`, `noop-prefix`, `count-postfix`, `count-prefix`, `nested-postfix` (on `CardPile:AddInternal`), `bool-prefix`, `ref-prefix`, `identity-transpiler`, `inner-postfix` (classified only), `gated-postfix squeeze|relic`, `gated-prefix squeeze`, `gated-or-postfix squeeze-relic`, `nearmiss-postfix squeeze`; each install logs PatchSafety's verdict as `FOREIGN classify` lines), `foreignpatch report [label]` (call counts as STATE lines, compared by compare.py), `foreignpatch require tolerated`, `foreignpatch classify <Type:Method>`, `foreignpatch remove`; also `bdperf foreign ...`. Scenarios `foreign-shapes-2k-on/off` (A/B), `foreign-controls` (must back off)
- `onfail continue` (a scenario expecting failures: by default the first `FAILED line`, an unknown command included, ends the session; a combat whose turn loop died fails every wait at once). `ladder.ps1 -Probe` also logs `bdperf piletimes` and `costhooks` after each turn's plays. `-ProbeStart`: the probed methods of the combat start.
`coop4.ps1 -Name coop4|coop4leak|coop4-10k|coopclient10k [-Peers 4] [-Rendered|-RenderedClient]`: more than two players, or a rendered client; `CHARACTER` in the client's script is set per peer. `coopleak` (parcoop, 26 fights) and `coopfights10k` (coop.ps1 -ClientHeadless -WithMods): what a run's next combats inherit; `gcfull` logs the live heap and `RunState._allCards`. The game keeps its last 20 checksum states: a heap climbing until then isn't a leak, fights with few actions take long to fill them. `bdperf release off`: the releases of Step U off, for comparison.
Snapshot scenarios ending in `cmd bdperf verify check` fail when a snapshot differed or none was verified (`snapcheck-freeturn` and `-old`, `snapcheck-purehooks`; `snapcheck-purehooks-wrong` is the positive control: its `expect` lines must see the difference).
`bdperf checksum|refresh|listeners|grid|pile|text|scan|plaque|sortkeys` compare with the game's own result, the whole mod off as `bdopt off` turns it off (not only the optimization under test), and fail when the mod is off or the optimization isn't applied or is off (it would be compared with itself). `bdperf refresh` sets every plain enchantment's values, the hand cards' preview values and highlight colors to values nothing computes before each side, so a refresh that skips its work is seen, compares what the hand refresh writes (each hand card's preview and enchanted values, its highlight) besides the checksum, then puts everything back. A comparison whose optimized side never took its own path (a back-off, a sort order or a walk left vanilla, no tab reused, no holder scanned) says `nothing to compare` or names what it didn't compare, never `OK`. `bdperf checksum` says `not compared` (never `OK`) when the filter or card reuse row's part is applied and on but served nothing while measured (`HookFilter.Served`, SnapshotCardReuse's reuses): a part another one's back-off idles (a new pile writer) does so by design, and `effects-check` proves each part serves in a normal session. Its cache row serving nothing is normal (HookSkip's filtered walks answer every hook) and only noted. `bdperf refresh` says how many dirtied values the game itself recomputed: most enchantments' `RecalculateValues` writes nothing, so theirs are compared as left.

Version check protocol (docs/RELEASE.md, "Version check protocol"): `python -I tools/check_versions.py [--local] [--log <log>] [--accept [--branch public|beta] [--accept-other-branch]]` compares the installed game/BaseLib/Limitless (and the other watched mods) with `tools/versions.json` and what Steam publishes, and lists what a session left vanilla. `--accept` records the installed versions as verified, refused while a published update isn't downloaded here; `--branch public|beta` says which branch a game copy outside Steam's library is (no appmanifest) when its version isn't verified yet; `--accept-other-branch` also records the build Steam publishes on the branch not installed here, only once the protocol ran on a copy of that build.
