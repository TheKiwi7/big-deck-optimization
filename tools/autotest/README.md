# Unattended in-game tests

Drive the real game with the **Debug** build's `AutoTest` runner (`src/BigDeckOptimization/Bench/AutoTest.cs`): it only
starts when the game is launched with `--bdtest <scenario>`, so normal launches are unaffected. Results (game logs,
traces) go to `results/` (gitignored).

| Script | What |
|---|---|
| `run.ps1 -Name <scenario> [-TraceSec 60] [-KeepConfig] [-Visible] [-Sound] [-Screen 1]` | Singleplayer through Steam (save profile 3, in memory only: your profiles and last-profile setting are untouched). The game window is moved off-screen (windowed 1920x1080, still rendering: same screenshots and fps) and gives the focus back to the window you were using; on a copy it starts hidden and takes no keyboard (through Steam it shows on screen `-Screen` for a moment, as Steam launches it); `-Visible` keeps it on screen. The game is muted (every master volume it sets is 0, your volume settings are untouched); `-Sound` keeps the sound. Only the window and the live volume change, not your settings. On a game copy (`-GameDir`) the session runs without Steam in its own user data, as `par.ps1`; `-KeepSlot` keeps that user data from the previous session (`settings.ps1`, `baselib-optional.ps1`, `limitless-switches.ps1`, for a check over a restart). Through Steam, your `mod_configs/BigDeckOptimization.cfg` (where `bdopt` saves with BaseLib) is restored byte for byte afterwards, unless `-KeepConfig`; if interrupted, copy back `results/BigDeckOptimization.cfg.run-backup`. `-PresentMon`: frame times measured outside the game (`winget install Intel.PresentMon.Console`); one column of pixels of the window stays on screen, Windows throttling a window entirely off it. `-GameDir <folder>`: a full copy of another game version (e.g. the beta branch copied to `C:\Games\StS2-beta-0.111.0`, with a `steam_appid.txt` containing `2868840` next to the exe) launched directly instead of through Steam, so tests can target it while Steam keeps another branch installed; deploy into it with `dotnet build ... -p:ModDeployDir=<folder>\mods\BigDeckOptimization`. |
| `coop.ps1 -Name coop [-WithMods] [-Visible] [-Sound] [-HostVisible]` | Local co-op: two instances without Steam (`--force-steam off --fastmp host_standard/join`), scenarios `<name>-host.txt` / `<name>-client.txt`. `-WithMods` copies your enabled Workshop mods into `<game>/mods_STEAMTEST` for the test and always deletes it afterwards. `-HostVisible` (scenario `cooptry`): you play the host, on screen with sound; a hidden scripted fake player plays its own turns and closes with you. `$env:STS2_GAME_DIR` points it at a game copy. |
| `try.ps1 [-Cleanup]` | Hands-on demo: a new run with ~16,800 cards and 736 relics (scenario `try-it`), then you play (`bdopt off` / `bdopt on` to compare). `-Cleanup` removes the local Debug copy afterwards. |
| `baselib-optional.ps1 -GameDir <copy>` | Two sessions with the mod list edited in a test slot (yours isn't touched): this mod loaded before BaseLib (the settings menu must still appear), then BaseLib disabled (every patch needing no other mod applies, bdopt works; Limitless and CampfireTrade fail to load, they need BaseLib). Ends with `ok` / `PROBLEM` lines. |
| `settings.ps1 -GameDir <copy>` | Two sessions in a test slot (your settings aren't touched): BaseLib's settings menu captured and an option turned off, then reloaded after a restart and turned back on (mods screen captured). Ends with `ok` / `PROBLEM` lines. |
| `mutations.ps1 [-GameDir <copy>] [-Only a,b] [-Scenario release-checks]` | How the mod reacts to game or mod updates: for each mutation of `tools/mutate` (compiler renumbering, a new hook, an unrelated change, a changed mirrored method / AbstractModel default / choice-context helper, a renamed method or field, a member made internal, a changed signature, changed Limitless or BaseLib code) gives each its own folder of hard links to a game copy, holding only the modified file (the copy itself is never written, stopping the script leaves nothing behind), runs them all in parallel, headless and without Steam (28 in about 2.5 minutes), and checks: the session ends, exactly the parts relying on the changed code are left vanilla (none for changes the mod doesn't rely on), no error from this mod, every bdperf comparison identical. Logs: `results/mutation-<name>.log`. |
| `release-incopy.ps1 -Copy <copy> [-WaitSec 120]` | The release package in game: the newest `dist/BigDeckOptimization-v*.zip` installed on a game copy in place of its Debug build, the account's Workshop mods beside it, one headless session without Steam, then the Debug build put back. Prints the version initialized, the patches applied, and any patch skipped, failed or disabled. Refuses a path under `steamapps`. Log: `results/<game version>/release-incopy.log`. |
| `python -I compare.py <a.log> <b.log>` | A/B check of two sessions: CHECKSUM, STATE and CARDPLAY lines must match line for line (prints IDENTICAL/DIFFERENT), then per-card `playcard` times side by side. |
| `sweep.ps1 -Name <scenario> [-GameDir <copy>] [-Start n] [-SessionTimeoutSec 1500]` | Runs a scenario with a `sweep cards\|relics\|potions\|encounters\|powers [first] [count] [checksum]` line to its end: an item leaving the game stuck ends the session (`SWEEP ABORT next=n`), a new session goes on from the next item; all logs in `results/<Name>.log`. A session restart means a fresh state: when two sweeps restarted at different items, what follows isn't comparable (rerun it in fresh sessions from that item). `sweep encounters KNIGHTS_ELITE checksum` runs one item by name, `sweeptimeout <s>` changes the 30 s limit per step. |
| `par.ps1 -Names a,b -GameDir <copy> [-Jobs 8] [-UseBaselines] [-Rendered]` | Scenarios in parallel, headless (`--headless`) and without Steam (`--force-steam off`: with Steam the game writes saves to Steam Cloud, and parallel sessions make cloud conflicts; mods from the copy's `mods_STEAMTEST`), each with its own `APPDATA`, a mirror of the user data in `%LOCALAPPDATA%\BigDeckOptimization\test-slots` without logs and runs in progress: your settings and saves aren't touched, and you can play meanwhile. Each session takes your account's display settings and the test profile's progress and preferences, so results and timings match sessions through Steam (checked: `ab-2k` identical, same turn times, same fps). `-Instant`: no animation waits, same results, several times faster mod on. Results are identical to a rendered session; **timings aren't meaningful** (one `run.ps1` session for fps). Every `x-off` / `x-on` pair is compared. A session is closed at `-TimeoutSec`, or when its log stays silent for `-StallSec` (240); one gone before its script's end starts over (`started over Nx`, its first log kept as `<log>.early`); a new one waits while under 3 GB of memory are free. `-UseBaselines`: a mod-off log already made with this game, these Workshop mods, this test tooling and this scenario isn't run again (`results/baselines/<version>/`); run without it once per release: a cached log can't show a change in the mod-off path itself. One series at a time, whatever the copy: the test slots are shared, a second series stops at once ("Another parallel test series uses the test slots"). |
| `parsweep.ps1 -Kind cards\|relics\|potions\|encounters\|powers -GameDir <copy> [-Jobs 16] [-ChunkItems 20] [-ItemTimeout 45] [-Speed instant\|fast] [-Chunks n,m] [-UseBaselines]` | A whole-game A/B through `par.ps1`'s sessions: `sweep-<Kind>-2k-off/on` cut into chunks with the same boundaries on both sides, so a cut only spoils its own chunk; a stuck item ends its session and the next goes on up to the chunk's end. Instant game speed by default (a whole relic sweep at both speeds is identical); `-Speed fast` once per release. `sweepreport.py` then says, chunk by chunk, what differs down to the values, what wasn't compared, items stopping a session, game errors on one side only, what each optimization did, what allocates the most: `results/<version>/report-<Kind>.md`, merged logs `sweep-<Kind>-2k-off/on.log`. `-OnExtra "enemyhp 999998"`: the positive control. |
| `ladder.ps1 -GameDir <copy> -Sizes "1,11,22" [-Coop] [-Plain] [-Party5] [-Turns 5] [-Tag x] [-TraceSec s] [-TraceDelaySec s]` | What deck size costs where a player sees it: the same rendered session at each size (the reference deck imported N times, the same card mix), uncapped, with `framedetail` and mouse plays. `-Coop`: the host renders, the client is headless (a second rendering instance would take the host's GPU). Co-op stays under 35 imports: the game's card ids are 16 bits on the network. Logs `lad-<tag>c<N>-host.log`, solo `lad-<tag>s<N>.log`. |
| `python -I ladderreport.py <log> <log> ...` | One table per moment (idle, hover, mouse plays, plays, end of turn, combat start), one row per log; the time of a play. |
| `python -I scalereport.py results/<version> 1 11 [kinds] [--top n]` | From `parsweep.ps1 -Imports 1` and `-Imports 11`: the items whose main thread time and allocations depend on the deck. Headless: finds heavy items, can't show that anything is smooth. |
| `python -I phasereport.py <log>` | A whole AutoSlay run (`autoslay-10k-on`) by kind of step: rooms, screens, map, fights. |
| `status.ps1 [-Watch]` | What the parallel sessions are doing (they have no window): progress, time left, each session's current item. |
| `python -I report.py <before.log> <after.log> [--markdown]` | Before/after table from `FPSSTAT`, `GCSTAT`, `SWEEP`, `GCFULL` and `played` lines; warns when one session ran under the game's fps cap or had a failed line. |
| `python -I check_scenarios.py` | Every scenario line is a command the runner knows. |
| `leakroots.ps1 -GameDir <copy> [-Scenario memory-runs-off]` | Who holds the runs a session left: dumps the process at the last menu, `dotnet-dump gcroot` on every `RunState`, counts the chains through this mod (exit 1 when any). |
| `parcoop.ps1 -Names coopfast,coopclone -GameDir <copy> [-Plain] [-Jobs 6] [-Instant]` | Co-op tests in parallel, headless and without Steam, each pair on its own local port (`--bdport`) and its own user data: nothing on screen, your settings untouched. Checks each peer's end, divergences, and that both saw the same enemy states. Equivalence only; `coop.ps1` for fps and hands-on. `-Plain`: no other Workshop mod. |
| `python -I effects.py <log> [--reference <log> --lost]` | What each optimization really did in a session (`effects` command, scenario `effects-check`): a counter at zero is an optimization that never ran. |

Prerequisites: a Debug build deployed (`dotnet build -c Debug`), `dotnet-trace` on PATH for traces, a run history file
copied to `%APPDATA%\SlayTheSpire2\bigdeck\ref.run` (scenarios import its decks and relics). Before the first co-op
test, launch the game once with `--force-steam off` and accept the mods warning (each non-Steam instance has its own
data folder, `%APPDATA%\SlayTheSpire2\default\<id>`).

## Scenario lines

One command per line, `#` comments, `{hash:NAME}` replaced by the hash of `bigdeck/NAME.run`.

- `newrun <CHARACTER> [seed]`, `mplobby <CHARACTER> [players]` (co-op lobby: pick and ready up)
- `wait <s>`, `waitfor menu|run|combat|idle|nocombat [timeout s]`, `timeout <s>` (whole script)
- `cmd <console command>` (networked commands go through the action queue in co-op)
- `play <n>`, `playcard <ID> [enemy index] [free]` (after `cmd card <ID> hand`; `free`: energy and star costs 0 first, not X costs; every card play, auto-plays included, is logged as `CARDPLAY`), `endturn`
- `enemyhp <hp>` (next combats), `state [label]` (creatures, powers, piles), `speed normal|fast|instant` (default fast)
- `deckview [s] [shot]`, `deckscroll <steps>`, `screenshot <name>`, `modsscreen <shot>`, `baselibmenu <shot>` (this mod's page in BaseLib's settings)
- `pilescroll draw|discard|exhaust <frames> [px]` (opens a combat pile view and moves its scroll target every frame like a held mouse wheel: open time, ms per frame, median/95th/worst; 3000 px steps redraw the whole grid like dragging the scrollbar)
- `language <code>` (game language for the session only, e.g. `fra`, `zhs`, `zht`; logs this mod's menu texts as `LANG` lines), `menuback` (closes the current main-menu submenu), `menutext <SLUG>` (logs an option's tooltip text, e.g. `HOOK_FILTER`, as `MENUTEXT`)
- `deckfilter [ID,ID...] [stacked]` (on the map: removes cards by id and, with `stacked`, those holding several stacked Limitless enchantments)
- `fakeconflict <Type:Method>` (a no-op postfix under another Harmony id, as another mod would patch that method: the optimization using it backs off and names it; `conflict-check`)
- `onfail continue` (a scenario expecting failures: by default the first `FAILED line`, an unknown command included, ends the session; a combat whose turn loop died fails every wait at once)
- `gcstat [label]` (wall time, GC pause time and collections since the previous gcstat), `gcfull [label]` (live heap after a full collection; after `tomenu`, also how many left runs are still alive), `tomenu` (leaves the run for the main menu), `autoslay <seed> [state]` (the game's own auto player: a whole run from the main menu instead of `newrun`, then it closes the game; the same run whenever and however fast a session plays it; `state`: the combat's state at each turn start), `autoslayfirst <console command>` (before `autoslay`: run as it enters its first room, e.g. a deck import, at the same point whatever the session's speed), `leakcheck [game|bench] [current|oldest] [label]` (paths from the static fields of the mod, or of the game and other mods, or of this test tooling, to the last left run; `oldest`: the first one still alive; `current`: the current run, the positive control)
- `fpsstat [label]` (frames since the previous fpsstat: average fps, 1% low, worst frame, frames over 33/50/100 ms), `framedetail` (each fpsstat also logs a `FRAMES` line: percentiles, process step, draw step, GPU, rest, main thread use, draw calls)
- `forcefocus` (the game's input code runs as in a focused window, mouse positions from the simulated mouse), `mousesweep <s>` (the mouse moves over the hand, creatures and top bar), `mouseplay <n>` (hover, drag, target, release; logs `MOUSEPLAY` and `PLAYTIME`), `controllermap default` (the game's default controller actions for the session, unsaved)
- `checksum [label] [vanilla]` (full combat state checksum, as co-op peers compare), `immortal [off]` (enemies never drop below 1 HP)
- `setenergy <n>`, `emptyhand`, `hover <enemy>` / `checktips [label]` (creature hover tips match the current tips)
- `counters [label]`: LimitlessReserialize kept/rebuilt lists and Debug verification mismatches, FastListeners cache counters
- Test sessions ignore the game's 30 fps cap in the background, so timings don't depend on window focus.
- `marker <text>`, `log <text>`, `quit`, `handoff` (stop answering card choices and leave the game to the player)
- Outside combat, with the game's own auto player (AutoSlay's room and screen handlers, found by their interfaces so every version works): `autoroom [remove] [<X>RestSiteOption] [timeout s]` (plays the current room: a combat room's fight like `play`/`endturn` then its rewards; shop: card removal first with `remove`, then random affordable items; rest site: the named option or a random one; treasure; event: random options; then every screen left (rewards, card rewards, upgrade, transform, enchant, deck choices) and the proceed; logs `AUTOROOM`), `automap [timeout s]` (the map handler travels to the next room, both votes in co-op; `AUTOMAP`), `runstate [label]` (each player's gold, HP, potions, relics and a hash of the deck as STATE lines, checked by compare.py and between co-op peers by parcoop.ps1), `selector ui|auto` (ui: no automatic card selector, the game's choice screens and their deck grids open and autoroom answers them; fights still get the selector), `barrier <label> [timeout s]` (co-op: waits until every player got there, through a networked `bigdeck mark`), `continuerun [timeout s]` (after `tomenu`: Continue on the main menu, the run comes back from its save), `waitfor room <type> [timeout s]` (that room entered, e.g. a co-op peer following the host's `cmd room Shop`). Scenarios `outside-2k-off/on` (par.ps1) and `outside-coop`, `outside-coopoff` (parcoop.ps1)

Card choices are answered with the first options, identically on every peer. The runner also fixes the `fight`
command's clock-based encounter seed (peers would desync) and skips Fur Coat when no map point exists yet.

Useful `bdperf` commands inside scenarios: `probe reset|log` (per-method times + long frames), `combatstart`,
`checks off` (no Debug-only vanilla re-checks: release-like timings), `pile [verify n]`, `verify`, `plaque [n]` (BaseLib's card type line, TypePlaqueSkip off vs on: same text object),
`probe nodes` (also every node callback: `_Process`, `_Input`, `_Draw`... and the engine entries `PackedScene.Instantiate`, `AddChild`...: where a long frame goes),
`piletimes [reset]` (SnapshotCardReuse's pile reads per pile and path: trusted, moved, dirty, full and why), `costhooks` (the cost and keyword listeners of the combat),
`dirtyreads on|off`, `purehooks on|off|blind` (written piles read only for their written cards; piles kept with pure listeners; blind: a positive control),
`costwrites` (does a cost change reach the write prefix, directly and through `SetToFreeThisTurn`), `upgradebench [n]` (an upgrade's steps per card, for Apotheosis).
Debug builds count card writes per method (`WRITES` line, with each card's pile) only with `BD_WRITES=1` in the environment or `--bdwrites`: the count costs a method lookup per write.
`ladder.ps1 -Probe` also logs `bdperf piletimes` and `costhooks` after each turn's plays.
Snapshot scenarios ending in `cmd bdperf verify check` fail in par.ps1 when a snapshot differed (`snapcheck-freeturn` and `-old`, `snapcheck-purehooks`; `snapcheck-purehooks-wrong` is the positive control, one problem expected).

Version check protocol (CLAUDE.md): `python -I tools/check_versions.py [--log <log>] [--accept]` compares the installed game/BaseLib/Limitless with `tools/versions.json` and lists what a session left vanilla.
