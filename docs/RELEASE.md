# Release procedure

## 1. Before releasing

"Every supported game version" below: v0.107.1 (public) and v0.113.1 (beta), each on its copy. v0.111.0, the former beta, is no longer distributed (since 2026-11-16 no check runs on it; its code paths stay in the DLL: DESIGN "Technical choices").

- [ ] Version check ("Version check protocol" below): `python -I tools/check_versions.py` says the installed game (on the branch Steam has installed: public, or a verified beta), BaseLib and Limitless, and the other watched mods (BetterSpire2, SpeedX, Unlimited), are the verified versions, also against what Steam publishes; otherwise follow the protocol before going on. Once the release checks pass, `--accept` again (versions unchanged too): it records the date the patches were last proven (`verified` in `tools/versions.json`).
- [ ] Manifest `dependencies` empty (BaseLib is optional: only `BigDeckOptimization.Menu.dll` references it).
- [ ] Version bumped in both `src/BigDeckOptimization/BigDeckOptimization.json` (`"version"`) and `BigDeckOptimization.csproj` (`<Version>`), `min_game_version` still right.
- [ ] `CHANGELOG.md` has a `## vX.Y.Z` section (the package script uses it as the Workshop change note).
- [ ] Debug build, singleplayer with a huge deck (`bigdeck import <ref> all`): `bdperf checksum 5`, `bdperf refresh 10`, `bdperf grid`, `bdperf pile`, `bdperf sortkeys` (game v0.113+; positive control `sortkeys-wrong`) all `OK: identical` (keep `checksum`/`refresh` under ~3,000 cards: they run vanilla first).
- [ ] Every runner judges each log with `tools/autotest/judge.py` (a failed line or console command, an error or a difference the mod found itself, a session cut short, a positive control that saw nothing): a `PROBLEM` line is a release blocker until explained, an `expected` line is a positive control doing its job.
- [ ] Equivalence A/Bs: `tools/autotest/par.ps1` and `parsweep.ps1 -Kind relics|potions|encounters|cards|powers` (parallel, headless, no Steam) without `-UseBaselines` once per release and version, `-Speed fast` once on one version; `report-<Kind>.md` says what differs, wasn't compared (every item in a chunk on both sides), or never ran; a session that started over (`started over Nx`) is a problem unless its `.early` log is the known renderer crash; a frozen session's `.frozenN` log is judged automatically (a freeze inside this mod's load is a problem of the job). `compare.py` also fails on game errors logged only, or far more often, with the mod on. fps and frame times in one `run.ps1` session alone. `python -I tools/autotest/check_scenarios.py` first.
- [ ] Fallbacks and switches, on every supported game version: `audit-toggles-2k` and `audit-conflict-ab` against `ab-2k-off` (every switch flipped in a combat; every back-off at once: `IDENTICAL`), `audit-listeners-ab` against `ab-2k-off`, `audit-deckcount-fault` against `deckcount-off`, `audit-finished-room-on` (`EFFECT FastCombatStart` stays 0 outside combat), `audit-verifier-relics` (`RelicStateReuse` stops growing), `audit-gc-latency` (`Interactive` twice), `parcoop.ps1 -Names audit-cooptoggle` and, with `-Plain`, `audit-waitspin` (`WAITSPIN` about 2,000, the frame given back).
- [ ] What players combine and what no other session does, on every supported game version: `$env:BDTEST_EXTRA_MODS = "SpeedX,ModConfig,sts2unlimited"` then `ab-2k-off/on`, `outside-2k-off/on`, `effects-check` and `parcoop.ps1 -Names coopfast,audit-coopdeath -OnOff` (peers agree; `coopfast` identical to its mod-off twin per peer; `audit-coopdeath`'s players play at once: their actions interleave in the shared queue at each session's pace and random targets land differently between an on and an off session, so it is peers only, its checksums after every action the proof); `audit-languages` (every language identical); `parcoop.ps1 -Names audit-coopdeath`; `started-off.ps1 -GameDir <copy>` (no `PROBLEM` line).
- [ ] Deck size: equivalence A/Bs run at ~1,900 cards (`ab-2k-off/on` = the 5-turn A/B, `pile-cards-2k-off/on`, `shuffle`, `coopclone`, `coopfast`), on every supported game version; the 8,400-card ones (`turns-off` vs `hookskip-on`, `pile-cards-off/on`) once per release, on one version: a few paths only run at large sizes (CardDbScan's pending overflow over 256 adds between walks, FastListeners' append journal over 4,096).
- [ ] Unattended checks (`tools/autotest`): `run.ps1 -Name solo-8k`, `run.ps1 -Name fast-start-check` (fast start, normal waits and mod off in three successive fights of one run: the waits are skipped and every patch stays on; its `STATE` lines differ by design, each fight changes the run: the equivalence is `ab-2k-off` vs `ab-2k-on`, fast start included, `IDENTICAL`), `parcoop.ps1 -Names coop,coopfast,coopclone,coopleak` and `-Names coopfast,coopleak -OnOff -Jobs 1` (`coop` and `coopclone` import the full reference deck for both players: mod off their combat start freezes the host past the network timeout and the game disconnects the client, one pair alone included (v0.113.1, 2026-11-15): their on/off comparison can't run; `coopleak`'s mod-off twin finishes on v0.107.1, not on v0.113: its combat starts are slower there) (same enemy states at each turn start on both peers, no `divergence`, and each peer's turn states, run states and settled checksums (after a barrier or the combat's end) identical to its mod-off twin's: `IDENTICAL` per role; `coopleak`: `run cards` flat, the heap flat once the game's 20 checksum states are full, about fight 21), `coop4.ps1 -Name coop4` and `coop4leak` (four players agree), `clonememo-check` (verified, enabled True), `settings.ps1 -GameDir <copy>` (no `PROBLEM` line: BaseLib menu shows every option, setting saved and reloaded, image on the mods screen), `baselib-optional.ps1 -GameDir <copy>` (no `PROBLEM` line: menu still appears when this mod loads before BaseLib; without BaseLib every patch applies and bdopt works), `run.ps1 -Name hookskip-off` then `hookskip-on` (identical CHECKSUM and STATE lines). Since v0.4.0, also (compare with `python -I tools/autotest/compare.py a.log b.log`: `IDENTICAL`): `release-checks` (the `bdperf` comparisons above, unattended), `pile-cards-off` / `pile-cards-on` (59 cards, every play logged; `counters end`: 0 mismatches), `turns-off` vs `hookskip-on` (everything off vs on, 5 turns), `shuffle-off` / `shuffle-on` (reshuffles), `snapcheck-hooks` (snapshots against the game's own while a cost listener comes and goes: the session fails on a difference), `combats3-2k-off` / `combats3-2k-on` (three combat starts in one session: what is kept from one clone to the next), `coop.ps1 -Name coopfast -WithMods` (both modded, the client's fast combat start switched off: it must still skip the waits in co-op, no divergence), `limitless-switches.ps1 -GameDir <copy>` (runs `limitless-absent` then `limitless-present`; no `PROBLEM` line: Limitless switches unticked without Limitless, ticked again with it). `coop-required.ps1` (the client without this mod is refused when joining: "Mods mismatch… BigDeckOptimization-vX.Y.Z"). `coop-modetag.ps1` (a client launched with the mod off is refused by a host with it on, the refusal naming `BigDeckOptimization-vX.Y.Z-off`; two players launched off join, their join lists saying `-off`). The mod-off co-op controls (`coopoff`, `coopclonevan`, `coopleakoff`, `outside-coopoff`, every `-OnOff` twin) are launched off (`launchoff`) and log `COOPMODETAG ...-off`. `coopvanilla` / `coopsolo1` / `coopsolo2` reproduce the mixed-setup failures (expected to diverge or freeze).
- [ ] No memory leak (`GCFULL` lines = live heap after a full collection), on every supported game version: `run.ps1 -Name memory-on` (15 turns at 8,400 cards: no steady growth from turn to turn), `memory-runs-on` vs `memory-runs-off` (4 runs of 2 fights, back to the main menu between runs): every `LEAKCHECK menuN` and `LEAKCHECK oldest` line finds no path from the mod's static fields to a left run, and `LEAKCHECK current`, the positive control in a fight, does find some. The game itself keeps every left run alive, mod off too (`left runs alive 4/4`, ~21 MB per run at 1,900 cards; `leakcheck game oldest` shows `NodePool`; `dotnet-dump` `gcroot` shows strong handles on `TweenHelper` closures of card trails), so the `GCFULL menu` lines grow either way; the mod adds ~3 MB per run at most: its weak tables' data (memos, one lot per run) attached to those same objects. A path, or a growth beyond that, is a release blocker until explained (`tools/autotest/leakroots.ps1` names who holds each run; `dotnet-gcdump` on and off at the last menu names the types).
- [ ] After a game update: `python -I tools/check_versions.py` (also what Steam publishes), `dotnet run --project tools/fpdiff -c Release -- review <old data dir> <new data dir> --decompiled <old> <new>` (only real changes of what patches rely on; review each, add `EquivalentFingerprints.cs` entries or adapt), then re-decompile the new version, `dotnet run --project tools/fpdiff -c Release -- hookfps <data dir> > fps-<version>.txt` for every version `HookSkipTable.cs` has rows for and `python -I tools/hookskip/classify.py <version> <decompiled dir> <fps file> ...` (all of them at once: the public version and the latest beta only; a version left out loses its own rows, but a hook matches any row of its name, so its hooks whose code, defaults and helpers equal a kept version's row stay filtered, untested there: on v0.111.0 all but AfterDeath, AfterTakingExtraTurn and ModifyDamageInternal, since 2026-11-16) to regenerate `HookSkipTable.cs` (a hook whose code, defaults or helpers changed stays vanilla until then). `tools/autotest/mutations.ps1` (40 mutations, about 2.5 minutes, the copy untouched; an undefined mutation fails unless `-AllowUndefined`) checks how the mod reacts to changed code.
- [ ] Release build in game (`python tools/release/package.py`, then `tools/autotest/release-incopy.ps1 -Copy <copy>` on each copy, or copy `dist/BigDeckOptimization-*.zip` content into `<game>/mods/` in place of the Debug install by hand):
  - the log shows `[BigDeckOptimization] Initialized vX.Y.Z` and every patch `applied`, except `CardSortKeys` on v0.107.1 (skipped: not needed there) and the patches of an optional mod not loaded (Limitless: `LimitlessReserialize`, `LimitlessRecalcSkip`, `LimitlessHookSkip`, `LimitlessCloneMemo`, `EnchantmentTabReuse`, `SnapshotCardReuse`; BaseLib: `TypePlaqueSkip`; BetterSpire2: ExtraScopes' BetterSpire2 scope);
  - `release-incopy.ps1` prints no `PROBLEMS` (judge.py's problems, a session not expected to end, and the `HarmonyRebuild: all N patched methods detoured` line present: no method of this mod's or another mod's left without its patches; with BaseLib, `BaseLibSettings: registered`: the package's settings menu loads; `Initialized` with the manifest's version; every Workshop mod found);
  - `bdopt` works, `bdperf` / `bigdeck` are unknown commands.
- [ ] Manifest `affects_gameplay: true` (since v0.4.0): a player without the mod, or with another version, gets the game's mod mismatch error when joining. Co-op with mixed setups desyncs or freezes with huge decks (DESIGN "Co-op with a player without the mod").
- [ ] Co-op with a player with the mod: `bdopt` on both, play a few combats, no desync, no `MISMATCH` / `disabled` lines in either log. During the run, `bdopt off` only warns (the mod stays on) until `bdopt off yes`, then `bdopt on` only warns until `bdopt on yes`, and the menu's master switch is greyed out either way. By hand too, in a co-op start lobby and in a saved co-op run's load lobby (Continue on a co-op save): `bdopt off` warns there.
- [ ] Back-offs: `conflict-check`, `audit-conflict-ab`, `audit-conflict-saves` and `audit-walk-conflict` pass their `runtimebackoff` lines (the runtime's own back-offs, not the preflight's identical log lines), `preflight-check` (a fake conflict at the menu listed by `bdopt why` before any runtime check).
- [ ] "Foreign patches judged by their shape" (DESIGN roadmap, "Foreign patches by shape"): its code is on the branch and on by default (`PatchSafety.ShapeRules`). Either it ships, after these checks pass (then its CHANGELOG item loses its pending mark), or the release sets `PatchSafety.ShapeRules` to false (every tolerant check then answers as the strict one, as before those rules: the fourth pass's state, not v1.0.3's, so with CardAscension `LimitlessCloneMemo` and `LimitlessHookSkip` then back off for every card, its `AddKeyword` prefix met strictly on their deeper clone chain) and drops that CHANGELOG item; never a release with it on and these checks not passed: `foreign-shapes-2k-on`/`-off` identical, `foreign-controls` with every expect seen, `parcoop.ps1 -Names coop-foreign -OnOff` (`STATE foreign` lines identical to the twins'), and `BDTEST_EXTRA_MODS` with RitsuLib, Zone the Spire, SynergyMod and CardAscension (`ab-2k-off/on`, `effects-check`, a co-op pair), on every supported game version.
- [ ] Optional mods most players use (BetterSpire2, SpeedX, ModConfig, Limitless) enabled at least once: no `disabled after exception` in the log.

## 3. Steam Workshop

The game has no uploader: use SteamCMD (https://developer.valvesoftware.com/wiki/SteamCMD).

1. Put a preview image (under 1 MB, square: Workshop lists show ~135 px thumbnails, so a big readable text beats a full screenshot) at `docs/workshop_preview.jpg` before packaging. Current one: a pile of 119 different real cards cut from in-game deck view captures (`tools/autotest`, scenario `card-art`, command `deckpages`), rotated at full size then scaled down (clean edges), with the card count in Kreon (SIL Open Font License). The same image, 512 px, is `src/BigDeckOptimization/mod_image.jpg` (mods screen; JPEG quality 97 with 4:4:4 color, e.g. Pillow `save(..., quality=97, subsampling=0, optimize=True)`: 242 KB, PSNR 42.5 dB vs the PNG). To change only the image on an existing item, run SteamCMD with a VDF holding just `appid`, `publishedfileid` and `previewfile`: subscribers and collections are kept (only deleting and recreating the item loses them).
2. Upload: `steamcmd +login <steam account> +workshop_build_item "<repo>\dist\workshop\workshop_item.vdf" +quit`
   - First upload (`docs/workshop_id.txt` absent): creates the item **hidden**, with title and description from `docs/workshop_description.bbcode`. SteamCMD prints the new item ID: save it in `docs/workshop_id.txt` so later uploads update that item (title/description are then edited on the page, not by the script).
   - Every upload adds an entry to the item's change notes, even with identical files, and entries can't be deleted (only edited, "Revert to this version" adds yet another one). To fix only a change note's text, use **Edit** on that entry on the change notes page: don't upload again.
3. On the item page: check the description and preview, add the game version tag if offered, then set visibility to Public. **Required items** (Owner Controls → Add/Remove Required Items) must stay empty: BaseLib is optional (the Workshop has no "optional item": it is linked from the description instead).
4. Subscribe on a second account or check that a subscriber gets the update. A local copy in `<game>/mods/` takes precedence over the Workshop one (the game disables the Workshop copy), so remove the local copy to test the Workshop version.

## 4. GitHub

1. Rename the CHANGELOG `## Unreleased` section to `## vX.Y.Z`, and remove its HTML comment (the Workshop change note is plain text: players would read it) and any pending mark; `package.py` refuses a section that still has either.
2. Commit, tag `vX.Y.Z`, push the tag.
3. Create a release from the tag: attach `dist/BigDeckOptimization-vX.Y.Z.zip`, paste the CHANGELOG section.

## 5. Nexus Mods

On demand only: same zip, same description.

## Version check protocol

When `python -I tools/check_versions.py` reports a game, BaseLib, Limitless, BetterSpire2, SpeedX or Unlimited version other than the verified ones (`tools/versions.json`; Steam may be on the `public-beta` branch: name the version explicitly to every other tool, `refs/v<version>` or a copy's data folder):

1. `dotnet run --project tools/compat -- src/BigDeckOptimization/bin/Debug/BigDeckOptimization.dll refs/v<version>`: every member of the DLL that version lacks.
2. A fresh session applying everything (`run.ps1 -Name release-checks`, with `BDTEST_EXTRA_MODS` for the optional mods), then `python -I tools/check_versions.py --log <its log>`: every patch skipped or failed, every part left vanilla, every method another mod now patches, every error or warning line of the mod.
3. `dotnet run --project tools/fpdiff -c Release -- review <old data dir> <new data dir> --decompiled <old> <new>` (`--old-mods/--new-mods` for a mod update): every fingerprinted method that really changed, with its diff and new callees.
4. For each: compare with what the patch mirrors or relies on, then add a reviewed entry to `EquivalentFingerprints.cs`, adapt the mirror (per version when a signature changed), or leave it vanilla and say so in DESIGN.md. A game update: `fpdiff hookfps` per version and `tools/hookskip/classify.py` with every supported version.
5. Prove it: the A/B scenarios touching that code identical without `-UseBaselines`, the `bdperf` comparisons OK, `mutations.ps1` if the reaction to changes was touched.
6. `python -I tools/check_versions.py --accept`: records what is installed (refused while a published update isn't downloaded; with Steam on a beta it adds that version to `betas` and keeps the public one).
