# Release procedure

## 1. Before releasing

"Every supported game version" below: v0.111.1 (public since 2026-11-17) and v0.114.0 (beta since 2026-11-25; v0.113.1 before it), each on its copy. v0.107.1, the former public version, and v0.111.0, the former beta, are no longer distributed (no check runs on them; their code paths stay in the DLL: DESIGN "Technical choices").

How a battery runs the items below on this PC (`tools/autotest/README.md`, "Shared slots"):

- One pool of solo slots for everything headless: `$SlotPool` (the logical processors less two, 14 on 16; `BDTEST_SLOTS`). Start the solo block, `par.ps1` on each copy, and the sweeps, `parsweep-all.ps1 -GameDir <public copy>,<beta copy>`, at the same time, each with its default `-Jobs` (the whole pool) or `-Jobs 14`, never `-Jobs 7` each (the slot range was each run's `-Jobs` before: two `-Jobs 7` runs shared slots 0-6). The memory guard (3 GB free) still holds every start.
- Longest first: every series orders its sessions by their last length (`results/<version>/durations.tsv`, else the scenario's last log), and a free slot goes to whichever series has the longest session waiting; a slot a series doesn't use goes back at once. Nothing to pass: the second battery of a release already starts its 8,400-card mod-off sides and the sweeps' long mod-off parts first.
- New and changed scenarios first: `battery.ps1` prints, before the first step, the scenarios that never ran on a copy's version or changed since their last log (`PRECHECK ... NEW|CHANGED`: they start first in the pool, `Test-ScenarioChanged`) and the `expect` lines of the other logs that never matched (`PRECHECK ... EXPECT`: leads, the code may have changed on purpose); while it runs, `EARLY <version> <name> <state>: <problem>` lines tell a failed session when it ends, not when its step does (`watch.sh` prints both).
- Baselines: the bullet below; Bench and the scenarios frozen before the first run, `-UseBaselines` on every rerun (`par.ps1`, `parsweep*.ps1`, `parcoop.ps1 -OnOff`, and `vanillacheck.ps1`, which reads its vanilla side and its sweep's "off" parts from them and always runs the patched-off side). The release battery asks for them in every step that has a mod-off side; `battery.ps1 -Fresh` (or `Fresh = $true` in its file) drops every `-UseBaselines` and gives `vanillacheck.ps1` `-Fresh`: the once-per-release-and-version run without baselines (the baselines are still kept as the sessions end).
- Pace-independent exclusive steps on both copies at once, and beside the solo block: `settings.ps1`, `baselib-optional.ps1`, `limitless-switches.ps1`, `started-off.ps1` (each process its own kept slot of 80-89, its logs in `results/<version>/`) and `mutations.ps1` (one run per copy, its sessions in the pool). `coop4.ps1 -Name coop4` and `coop4leak` side by side (slots 49-52). Co-op on/off at 1,900 cards: `parcoop.ps1 ... -OnOff -UseBaselines -OffJobs 1 -Jobs 3` (one mod-off pair at a time, mod-on pairs beside it) and read each pair's longest frame: a `NETWORK MARGIN` problem means that pair ran too near the 20 s disconnect, so run it with `-Jobs 1`.
- Still alone on their copy or the PC: `started-off-nomenu.ps1` (sets the copy's menu DLL aside), `release-incopy.ps1` (replaces the copy's Debug build), `continue-check.ps1`, `coop.ps1` and the scripts built on it (`coop-required.ps1`, `coop-modetag.ps1`: slot 70, the game's own port), and every timing (`run.ps1` without `-KeepSlot`, which refuses to start beside another game; `ladder.ps1`, fps, `memory-on`): run it with nothing else going.

## Version check protocol

When `python -I tools/check_versions.py` reports a game, BaseLib, Limitless, BetterSpire2 or SpeedX version other than the verified ones (`tools/versions.json`; Steam may be on the `public-beta` branch: name the version explicitly to every other tool, `refs/v<version>` or a copy's data folder):

1. `dotnet run --project tools/compat -- src/BigDeckOptimization/bin/Debug/BigDeckOptimization.dll refs/v<version>`: every member of the DLL that version lacks.
2. A fresh session applying everything (`run.ps1 -Name release-checks`, with `BDTEST_EXTRA_MODS` for the optional mods), then `python -I tools/check_versions.py --log <its log>`: every patch skipped or failed, every part left vanilla, every method another mod now patches, every error or warning line of the mod. Also `effects-check` (its "NEVER RAN" names a patch applied but doing nothing: v0.114.0's pinned display sets, before `--log` knew CodeSet's line).
3. `dotnet run --project tools/fpdiff -c Release -- review <old data dir> <new data dir> --decompiled <old> <new>` (`--old-mods/--new-mods` for a mod update): every fingerprinted method that really changed, with its diff and new callees.
4. For each: compare with what the patch mirrors or relies on, then add a reviewed entry to `EquivalentFingerprints.cs`, adapt the mirror (per version when a signature changed), or leave it vanilla and say so in DESIGN.md. A game update: `fpdiff hookfps` per version and `tools/hookskip/classify.py` with every supported version.
5. Prove it: the A/B scenarios touching that code identical without `-UseBaselines`, the `bdperf` comparisons OK, `mutations.ps1` if the reaction to changes was touched.
6. `python -I tools/check_versions.py --accept`: records what is installed (refused while a published update isn't downloaded; with Steam on a beta it adds that version to `betas` and keeps the public one).
