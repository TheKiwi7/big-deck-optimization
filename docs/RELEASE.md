# Release procedure

## 1. Before releasing

"Every supported game version" below: v0.111.1 (public since 2026-11-17) and v0.113.1 (beta), each on its copy. v0.107.1, the former public version, and v0.111.0, the former beta, are no longer distributed (no check runs on them; their code paths stay in the DLL: DESIGN "Technical choices").

- [ ] Version check ("Version check protocol" below): `python -I tools/check_versions.py` says the installed game (on the branch Steam has installed: public, or a verified beta), BaseLib and Limitless, and the other watched mods (BetterSpire2, SpeedX, Unlimited), are the verified versions, also against what Steam publishes; otherwise follow the protocol before going on. Once the release checks pass, `--accept` again (versions unchanged too): it records the date the patches were last proven (`verified` in `tools/versions.json`).

- [ ] `CHANGELOG.md` has a `## vX.Y.Z` section (the package script uses it as the Workshop change note).
- [ ] Debug build, singleplayer with a huge deck (`bigdeck import <ref> all`): `bdperf checksum 5`, `bdperf refresh 10`, `bdperf grid`, `bdperf pile`, `bdperf sortkeys` (game v0.113+; positive control `sortkeys-wrong`) all `OK: identical` (keep `checksum`/`refresh` under ~3,000 cards: they run vanilla first).
- [ ] Every runner judges each log with `tools/autotest/judge.py` (a failed line or console command, an error or a difference the mod found itself, a session cut short, a positive control that saw nothing, a `bdperf` comparison that compared nothing (`not applied ...: nothing to compare`, `left the walks vanilla`, `not compared:`) unless the scenario declares it (`# uncompared:`, or an `expect`), the effects a scenario names (`# effects-ran:`) still at zero, an `expect` line of the script never reached (an ABORT before it)): a `PROBLEM` line is a release blocker until explained, an `expected` line is a positive control doing its job.
- [ ] `bdopt off` is the unmodified game, on every supported game version: `tools/autotest/vanillacheck.ps1 -GameDir <copy>` (`ab-2k-off`, `outside-2k-off` and a potions sweep, each both vanilla, launched with `--bdvanilla`, and patched-off, every patch installed then `bdopt off`: `IDENTICAL`, exit code 0). This is what lets the mod-off sides below run vanilla and come from the baselines. Solo only: co-op mod-off sides (`parcoop.ps1`, `coop.ps1`, `coop4.ps1`) still launch with `--bdoff`, every patch installed.
- [ ] Baselines, before the battery: commit (freeze) `src/BigDeckOptimization/Bench` and the scenarios first. The battery's first run then runs each mod-off side once, vanilla (`--bdvanilla`), and keeps it (`results/baselines/<version>/`, solo; `results/baselines/<version>/coop/` for `parcoop.ps1 -OnOff`'s twins); every rerun of the battery or of a failed step passes `-UseBaselines` and reuses them, while their key holds (game, test mods and their files, run files, profiles, `mod_configs`/`mod_data`, the scenario, and the code of the `Bench` files it runs: a comment or layout edit there keeps the key, a code edit renews only the scenarios running that file). A `Bench` code change between a battery's first run and its reruns means mod-off sides running again: make it before, or accept the cost. Once per release and version a run without `-UseBaselines` (`vanillacheck.ps1` is the proof a vanilla side stands for `bdopt off`).
- [ ] Equivalence A/Bs: `tools/autotest/par.ps1` and `parsweep.ps1 -Kind relics|potions|encounters|cards|powers` (parallel, headless, no Steam; the five kinds at once on one copy: `parsweep-all.ps1 -GameDir <copy>`, each kind's output in `results/<version>/parsweep-<kind>.out`, progress in `status-<kind>.txt`) on every supported game version, `-UseBaselines` allowed: a mod-off side is a vanilla session (`--bdvanilla`, no patch of this mod installed), reused from the baselines while their key (game, test mods and their data, run files, profile, `mod_configs`, the `Bench` parts the scenario runs, the scenario) is unchanged. The game has no uploader: use SteamCMD (https://developer.valvesoftware.com/wiki/SteamCMD).

1. Put a preview image (under 1 MB, square: Workshop lists show ~135 px thumbnails, so a big readable text beats a full screenshot) at `docs/workshop_preview.jpg` before packaging. Current one: a pile of 119 different real cards cut from in-game deck view captures (`tools/autotest`, scenario `card-art`, command `deckpages`), rotated at full size then scaled down (clean edges), with the card count in Kreon (SIL Open Font License). The same image, 512 px, is `src/BigDeckOptimization/mod_image.jpg` (mods screen; JPEG quality 97 with 4:4:4 color, e.g. Pillow `save(..., quality=97, subsampling=0, optimize=True)`: 242 KB, PSNR 42.5 dB vs the PNG). To change only the image on an existing item, run SteamCMD with a VDF holding just `appid`, `publishedfileid` and `previewfile`: subscribers and collections are kept (only deleting and recreating the item loses them).
2. Upload: `steamcmd +login <steam account> +workshop_build_item "<repo>\dist\workshop\workshop_item.vdf" +quit`
   - First upload (`docs/workshop_id.txt` absent): creates the item **hidden**, with title and description from `docs/workshop_description.bbcode`. SteamCMD prints the new item ID: save it in `docs/workshop_id.txt` so later uploads update that item (title/description are then edited on the page, not by the script).
   - Every upload adds an entry to the item's change notes, even with identical files, and entries can't be deleted (only edited, "Revert to this version" adds yet another one). To fix only a change note's text, use **Edit** on that entry on the change notes page: don't upload again.
3. On the item page: check the description and preview, add the game version tag if offered, then set visibility to Public. **Required items** (Owner Controls → Add/Remove Required Items) must stay empty: BaseLib is optional (the Workshop has no "optional item": it is linked from the description instead).
4. Subscribe on a second account or check that a subscriber gets the update. A local copy in `<game>/mods/` takes precedence over the Workshop one (the game disables the Workshop copy), so remove the local copy to test the Workshop version.

## Version check protocol

When `python -I tools/check_versions.py` reports a game, BaseLib, Limitless, BetterSpire2, SpeedX or Unlimited version other than the verified ones (`tools/versions.json`; Steam may be on the `public-beta` branch: name the version explicitly to every other tool, `refs/v<version>` or a copy's data folder):

1. `dotnet run --project tools/compat -- src/BigDeckOptimization/bin/Debug/BigDeckOptimization.dll refs/v<version>`: every member of the DLL that version lacks.
2. A fresh session applying everything (`run.ps1 -Name release-checks`, with `BDTEST_EXTRA_MODS` for the optional mods), then `python -I tools/check_versions.py --log <its log>`: every patch skipped or failed, every part left vanilla, every method another mod now patches, every error or warning line of the mod.
3. `dotnet run --project tools/fpdiff -c Release -- review <old data dir> <new data dir> --decompiled <old> <new>` (`--old-mods/--new-mods` for a mod update): every fingerprinted method that really changed, with its diff and new callees.
4. For each: compare with what the patch mirrors or relies on, then add a reviewed entry to `EquivalentFingerprints.cs`, adapt the mirror (per version when a signature changed), or leave it vanilla and say so in DESIGN.md. A game update: `fpdiff hookfps` per version and `tools/hookskip/classify.py` with every supported version.
5. Prove it: the A/B scenarios touching that code identical without `-UseBaselines`, the `bdperf` comparisons OK, `mutations.ps1` if the reaction to changes was touched.
6. `python -I tools/check_versions.py --accept`: records what is installed (refused while a published update isn't downloaded; with Steam on a beta it adds that version to `betas` and keeps the public one).
