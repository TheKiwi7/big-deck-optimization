# Release procedure

## 1. Before releasing

- [ ] Version check protocol (CLAUDE.md): `python -I tools/check_versions.py` says the installed game, BaseLib and Limitless are the verified versions; otherwise follow the protocol (`--log` on a fresh session, adapt or leave vanilla, A/B checks, `--accept`) before going on.
- [ ] Manifest `dependencies` empty (BaseLib is optional: only `BigDeckOptimization.Menu.dll` references it).
- [ ] Version bumped in both `src/BigDeckOptimization/BigDeckOptimization.json` (`"version"`) and `BigDeckOptimization.csproj` (`<Version>`), `min_game_version` still right.
- [ ] `CHANGELOG.md` has a `## vX.Y.Z` section (the package script uses it as the Workshop change note).
- [ ] Debug build, singleplayer with a huge deck (`bigdeck import <ref> all`): `bdperf checksum 5`, `bdperf refresh 10`, `bdperf grid`, `bdperf pile` all `OK: identical` (keep `checksum`/`refresh` under ~3,000 cards: they run vanilla first).
- [ ] Equivalence A/Bs: `tools/autotest/par.ps1` and `parsweep.ps1 -Kind relics|potions|encounters|cards|powers` (parallel, headless, no Steam) without `-UseBaselines` once per release and version, `-Speed fast` once on one version; `report-<Kind>.md` says what differs, wasn't compared, or never ran. fps and frame times in one `run.ps1` session alone. `python -I tools/autotest/check_scenarios.py` first.
- [ ] Fallbacks and switches, on every supported game version: `audit-toggles-2k` and `audit-conflict-ab` against `ab-2k-off` (every switch flipped in a combat; every back-off at once: `IDENTICAL`), `audit-listeners-ab` against `ab-2k-off`, `audit-deckcount-fault` against `deckcount-off`, `audit-finished-room-on` (`EFFECT FastCombatStart` stays 0 outside combat), `audit-verifier-relics` (`RelicStateReuse` stops growing), `audit-gc-latency` (`Interactive` twice), `parcoop.ps1 -Names audit-cooptoggle` and, with `-Plain`, `audit-waitspin` (`WAITSPIN` about 2,000, the frame given back).
- [ ] What players combine and what no other session does, on every supported game version: `$env:BDTEST_EXTRA_MODS = "SpeedX,ModConfig,sts2unlimited"` then `ab-2k-off/on`, `outside-2k-off/on`, `effects-check` and `parcoop.ps1 -Names coopfast,audit-coopdeath` (identical, peers agree); `audit-languages` (every language identical); `parcoop.ps1 -Names audit-coopdeath`; `started-off.ps1 -GameDir <copy>` (no `PROBLEM` line).
- [ ] Deck size: equivalence A/Bs run at ~1,900 cards (`ab-2k-off/on` = the 5-turn A/B, `pile-cards-2k-off/on`, `shuffle`, `coopclone`, `coopfast`), on every supported game version; the 8,400-card ones (`turns-off` vs `hookskip-on`, `pile-cards-off/on`) once per release, on one version: a few paths only run at large sizes (CardDbScan's pending overflow over 256 adds between walks, FastListeners' append journal over 4,096).
- [ ] Unattended checks (`tools/autotest`): `run.ps1 -Name solo-8k`, `run.ps1 -Name fast-start-check` (fast start, normal waits and mod off in three successive fights of one run: the waits are skipped and every patch stays on; its `STATE` lines differ by design, each fight changes the run: the equivalence is `ab-2k-off` vs `ab-2k-on`, fast start included, `IDENTICAL`), `parcoop.ps1 -Names coop,coopfast,coopclone,coopleak` (same enemy states at each turn start on both peers, no `divergence`; `coopleak`: `run cards` flat, the heap flat once the game's 20 checksum states are full, about fight 21), `coop4.ps1 -Name coop4` and `coop4leak` (four players agree), `clonememo-check` (verified, enabled True), `settings.ps1 -GameDir <copy>` (no `PROBLEM` line: BaseLib menu shows every option, setting saved and reloaded, image on the mods screen), `baselib-optional.ps1 -GameDir <copy>` (no `PROBLEM` line: menu still appears when this mod loads before BaseLib; without BaseLib every patch applies and bdopt works), `run.ps1 -Name hookskip-off` then `hookskip-on` (identical CHECKSUM and STATE lines). Since v0.4.0, also (compare with `python -I tools/autotest/compare.py a.log b.log`: `IDENTICAL`): `release-checks` (the `bdperf` comparisons above, unattended), `pile-cards-off` / `pile-cards-on` (59 cards, every play logged; `counters end`: 0 mismatches), `turns-off` vs `hookskip-on` (everything off vs on, 5 turns), `shuffle-off` / `shuffle-on` (reshuffles), `snapcheck-hooks` (snapshots against the game's own while a cost listener comes and goes: the session fails on a difference), `combats3-2k-off` / `combats3-2k-on` (three combat starts in one session: what is kept from one clone to the next), `coop.ps1 -Name coopfast -WithMods` (both modded, the client's fast combat start switched off: it must still skip the waits in co-op, no divergence), `run.ps1 -Name limitless-menu` via `limitless-switches.ps1 -GameDir <copy>` (no `PROBLEM` line: Limitless switches unticked without Limitless, ticked again with it). `coop-required.ps1` (the client without this mod is refused when joining: "Mods mismatch… BigDeckOptimization-vX.Y.Z"). `coopvanilla` / `coopsolo1` / `coopsolo2` reproduce the mixed-setup failures (expected to diverge or freeze).
- [ ] No memory leak (`GCFULL` lines = live heap after a full collection), on every supported game version: `run.ps1 -Name memory-on` (15 turns at 8,400 cards: no steady growth from turn to turn), `memory-runs-on` vs `memory-runs-off` (4 runs of 2 fights, back to the main menu between runs): every `LEAKCHECK menuN` and `LEAKCHECK oldest` line finds no path from the mod's static fields to a left run, and `LEAKCHECK current`, the positive control in a fight, does find some. The game itself keeps every left run alive, mod off too (`left runs alive 4/4`, ~21 MB per run at 1,900 cards; `leakcheck game oldest` shows `NodePool`; `dotnet-dump` `gcroot` shows strong handles on `TweenHelper` closures of card trails), so the `GCFULL menu` lines grow either way; the mod adds ~3 MB per run at most: its weak tables' data (memos, one lot per run) attached to those same objects. A path, or a growth beyond that, is a release blocker until explained (`tools/autotest/leakroots.ps1` names who holds each run; `dotnet-gcdump` on and off at the last menu names the types).
- [ ] After a game update: `python -I tools/check_versions.py` (also what Steam publishes), `dotnet run --project tools/fpdiff -c Release -- review <old data dir> <new data dir> --decompiled <old> <new>` (only real changes of what patches rely on; review each, add `EquivalentFingerprints.cs` entries or adapt), then re-decompile the new version, `dotnet run --project tools/fpdiff -c Release -- hookfps <data dir> > fps-<version>.txt` for every supported version and `python -I tools/hookskip/classify.py <version> <decompiled dir> <fps file> ...` (all supported versions at once) to regenerate `HookSkipTable.cs` (a hook whose code, defaults or helpers changed stays vanilla until then). `tools/autotest/mutations.ps1` (about 2.5 minutes, the copy untouched) checks how the mod reacts to changed code.
- [ ] Release build in game (`python tools/release/package.py`, then `tools/autotest/release-incopy.ps1 -Copy <copy>` on each copy, or copy `dist/BigDeckOptimization-*.zip` content into `<game>/mods/` in place of the Debug install by hand):
  - the log shows `[BigDeckOptimization] Initialized vX.Y.Z` and every patch `applied` (`EnchantmentTabReuse` only with Limitless);
  - `bdopt` works, `bdperf` / `bigdeck` are unknown commands.
- [ ] Manifest `affects_gameplay: true` (since v0.4.0): a player without the mod, or with another version, gets the game's mod mismatch error when joining. Co-op with mixed setups desyncs or freezes with huge decks (DESIGN "Co-op with a player without the mod").
- [ ] Co-op with a player with the mod: `bdopt` on both, play a few combats, no desync, no `MISMATCH` / `disabled` lines in either log.
- [ ] Optional mods most players use (BetterSpire2, SpeedX, ModConfig, Limitless) enabled at least once: no `disabled after exception` in the log.

## 2. Package

```
python -I tools/release/package.py
```

Produces in `dist/` (gitignored): `BigDeckOptimization-vX.Y.Z.zip` and `workshop/` (content folder + `workshop_item.vdf`).

## 3. Steam Workshop

The game has no uploader: use SteamCMD (https://developer.valvesoftware.com/wiki/SteamCMD).

1. Put a preview image (under 1 MB, square: Workshop lists show ~135 px thumbnails, so a big readable text beats a full screenshot) at `docs/workshop_preview.jpg` before packaging. Current one: a pile of 119 different real cards cut from in-game deck view captures (`tools/autotest`, scenario `card-art`, command `deckpages`), rotated at full size then scaled down (clean edges), with the card count in Kreon (SIL Open Font License). The same image, 512 px, is `src/BigDeckOptimization/mod_image.jpg` (mods screen; JPEG quality 97 with 4:4:4 color, e.g. Pillow `save(..., quality=97, subsampling=0, optimize=True)`: 242 KB, PSNR 42.5 dB vs the PNG). To change only the image on an existing item, run SteamCMD with a VDF holding just `appid`, `publishedfileid` and `previewfile`: subscribers and collections are kept (only deleting and recreating the item loses them).
2. Upload: `steamcmd +login <steam account> +workshop_build_item "<repo>\dist\workshop\workshop_item.vdf" +quit`
   - First upload (`docs/workshop_id.txt` absent): creates the item **hidden**, with title and description from `docs/workshop_description.bbcode`. SteamCMD prints the new item ID: save it in `docs/workshop_id.txt` so later uploads update that item (title/description are then edited on the page, not by the script).
   - Every upload adds an entry to the item's change notes, even with identical files, and entries can't be deleted (only edited, "Revert to this version" adds yet another one). To fix only a change note's text, use **Edit** on that entry on the change notes page: don't upload again.
3. On the item page: check the description and preview, add the game version tag if offered, then set visibility to Public. **Required items** (Owner Controls → Add/Remove Required Items) must stay empty: BaseLib is optional (the Workshop has no "optional item": it is linked from the description instead).
4. Subscribe on a second account or check that a subscriber gets the update. A local copy in `<game>/mods/` takes precedence over the Workshop one (the game disables the Workshop copy), so remove the local copy to test the Workshop version.

## 4. GitHub

1. Rename the CHANGELOG `## Unreleased` section to `## vX.Y.Z`.
2. Commit, tag `vX.Y.Z`, push the tag.
3. Create a release from the tag: attach `dist/BigDeckOptimization-vX.Y.Z.zip`, paste the CHANGELOG section.
